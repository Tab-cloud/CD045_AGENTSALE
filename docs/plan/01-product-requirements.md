# 产品需求与业务流程

版本：v0.1 / 2026-09-06。需求编号用于后续任务、测试与交付追踪。

## 1. 用户与权限

| 角色 | 工作 | 权限边界 |
|---|---|---|
| 经营负责人 | 选市场、预算、定价、合作、查看利润 | 管理授权及连接器；审批超限行为 |
| 运营人员 | 评估商品、内容审阅、客户跟进 | 可执行其授权范围内的发布与沟通 |
| 履约/客服 | 跟踪订单、处理售后 | 只读供货必要信息；退款按权限 |
| 海外客户 | 浏览、购买、询问、查询订单 | 仅能访问自己的订单 |

工厂首版通过邮件/人工录入和订单导出协作，无需工厂注册后台。界面中的 Agent 不拥有独立经营权限，执行权限继承明确的工作区规则和发起人限制。

## 3. 商品与供应商流程

### 3.1 发现和核实

输入：目标国家、候选品类、价格区间、物流约束、来源范围、查找数量与成本上限。目标市场未配置时只允许收集候选，不能给出面向真实市场的开售结论。

步骤：保存来源 → 提取产品 → 识别重复 → 标记厂家/贸易商/待核实 → 保存证据 → 发起市场分析。主体核验至少记录名称、地区、联系人、生产能力证据、核验方式和日期，不将网页自述当作已核实资质。

供应商询价字段：SKU 与变体、人民币供货价、有效期、含税情况、起订量、单件代发、包装后重量尺寸、处理时效、库存刷新方式、出口配合能力、样品条件、素材使用权、缺货替代规则、质量问题和退换责任。

沟通可以由 Agent 起草/在授权后发送；签订合作与特殊承诺需要经营负责人确认。联系对象来自明确业务资料，不把自动群发当作首版获客策略。

### 3.2 市场评估

评估维度：需求证据、竞品与成交价格证据、可展示的差异、供应确定性、跨境物流、准入待办、预期利润、售后负担。价格观察需注明时间、运费是否包含、是否只是标价。

输出必须包含：事实、估算、缺失项、证据链接、敏感性分析和下一步。LLM 可解释和提出假设；利润和得分由可测试的公式计算。证据覆盖率独立于商业评分展示，不能用漂亮的综合分掩盖缺失运费。

商品经营状态：`candidate → researching → awaiting_evidence → test_ready → testing → approved → listed → paused → retired`。补证完成可回到 researching；测试失败转 paused/retired；批准不等于已经发布。每次转换记录执行者和原因。

### 3.3 上架门槛

明确目标市场、可信规格与图片、可售 SKU、有效供货与运费、样品结果或书面样品豁免理由、素材授权、该市场准入事项核实、售价与交期、支付可用、退款与退货安排。

价格和库存采用新鲜度策略：报价按有效期，库存试点默认最多 24 小时需刷新，具体由供货协议覆盖。过期或来源未知时暂停新增购买/转询盘，不自动承诺现货。

## 4. 内容与推广流程

输入为商品事实版本、目标受众、语言、渠道规格、素材版权信息、价格与优惠有效期。

首版默认生成 15–30 秒竖屏视频：场景问题 → 真实商品与卖点 → 可证实的使用方式 → 按渠道允许方式引导访问店铺。优先实拍素材剪辑、字幕和配音，AI 生成人物/场景是可选能力，不能改变产品真实结构和效果。

记录每条文案主张的 `claim_id`、证据、适用市场、有效期。工厂资料变化后，关联草稿需要重新审阅；已发布内容进入修订/下架待办。

内容状态：`draft → generating → review_required → approved → scheduled → published`；旁路为 `generation_failed / rejected / publish_unknown / withdrawn`。通过审阅不代表发布成功；必须有平台回执或人工登记的可核实链接。

归因：每条内容绑定 campaign、content、渠道、商品与市场；UTM 和店铺订单属性保存来源。首版采用“可追踪的最后一次非直接点击，建议 7 天窗口”，并保留 unknown，不用模型猜测归因；跨设备和缺失授权的情况不保证可追踪。

## 5. 客户与销售流程

客户阶段：`new → qualified → considering → checkout_sent → purchased`，并保留 `lost / do_not_contact`。

基础客服仅引用已确认商品资料、有效价格、配送范围和订单状态。缺少运费或功能证据时解释待确认，并生成待办。展示客户原文和译文；客户明确表达与模型推断分开保存，推断不作为事实。

跟进对象分为主动询盘与营销订阅；交易通知不等于营销许可。首版对无回复的营销跟进默认最多 2 次、至少间隔 48 小时、按客户当地可联系时段执行，具体以渠道及目标市场规则覆盖。退订/明确拒绝立刻抑制后续营销任务。

常规解释与授权价格范围内报价可自动化；超底价、改交期、提供赔偿、定制合同等升级处理。退款执行由权限规则控制，客服对话不能直接修改支付状态。

## 6. 订单、采购与履约

支付、履约、售后分开建模，避免单一状态无法表达“部分发货 + 部分退款”。

| 维度 | 核心状态 | 权威来源 |
|---|---|---|
| 支付 | pending / authorized / paid / partially_refunded / refunded / failed | 电商平台及其支付记录 |
| 履约 | unallocated / supplier_pending / accepted / partially_shipped / shipped / delivered / exception / cancelled | 采购接单记录、履约商/承运商证据 |
| 售后 | none / opened / awaiting_return / resolution_pending / resolved | 售后记录与退款回执 |

付款确认后检查风控状态、地址、库存及供货价，再创建供应商订单。不把浏览器支付返回页当成付款证据。取消与发货冲突需查询外部最新状态；部分退款不能把整单标为已退。

采购按 SKU 与供应商拆单。一个客户订单可对应多个采购单和包裹；订单行锁定销售规格、售价、成本估算、工厂报价版本与交期快照。试点可只运营单供应商订单，数据模型保留拆单能力。

首版采购通知可人工导出、核实发送后记录，或通过已授权邮件发送；默认不自动支付供应商。缺货不擅自换款；物流号不等于已经揽收；超过承诺处理时间进入异常队列。

## 7. 利润与实验

实收净销售收入 = 商品与运费实收 − 已退款金额 − 代收代缴税额。贡献利润 = 实收净销售收入 − 实际采购 − 实际物流/关税承担 − 支付及平台费用 − 获客成本 − 售后额外损耗 − 分摊 AI/内容成本。退款本金已从收入扣除，不再次记入售后损耗。

价格含税/未含税、运费收取方式必须在计算输入中明确。估算阶段以“预期净收入”和情景成本计算，不混用实际利润。会计利润、公司固定成本、所得税不包含在贡献利润内，界面标明口径。

所有金额使用货币代码和整数最小货币单位/精确十进制，禁止浮点直接结算。换汇保存方向、来源、时间和汇率版本。采购可为 CNY，展示币种按市场设置，历史订单不随新汇率重算。

实验配置：SKU × 市场、假设、时间窗口、渠道、内容变体、预算、获客成本上限、停止条件、结果与样本量。开发样稿中的金额与阈值完全是演示，不作为市场建议。

## 8. 首次使用

创建工作区 → 选择演练模式 → 导入示例 → 看完整流程 → 配置目标市场/供应商/预算 → 连接店铺与其他服务 → 分项验证 → 由负责人开启对应真实能力。

没有真实数据时展示“尚无真实订单”和导入入口，不能用示例销售额填充正式经营页。更多验收案例见 [交付计划](06-delivery-roadmap.md)。
