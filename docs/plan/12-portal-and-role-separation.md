# 管理与运营门户隔离

版本：v0.4 / 2026-09-06。

AgentSale 在本机启动两个独立的 Next.js 前端应用。运营工作台使用端口 3045，管理控制台使用端口 3047。两者拥有不同的入口、页面树、布局、导航和角色门禁。

| 门户 | 允许角色 | 能力 |
|---|---|---|
| 运营工作台 | `operator` | 商品、供应商、来源资料、成本、自动化、内容、素材和内部审阅 |
| 管理控制台 | `admin` | 模型与搜索服务、密钥、调用额度、账号和调用记录 |

管理员不继承运营权限。访问运营门户时，管理员会看到管理控制台入口，业务页面不会渲染；运营账号访问管理门户时同理。前端门禁只用于清晰体验，最终权限由服务端执行。

后端接口按精确角色划分：

- `/api/v1/admin` 仅管理员；
- `/api/v1/state`、`commands`、`automation`、`media` 和 `files` 仅运营；
- `/api/v1/auth` 供两个门户登录和注销。

管理前端不打开第二份 PGlite 数据库。它通过固定的本机代理访问 3045 的身份和管理接口，代理只允许 `auth` 与 `admin` 两个名称，拒绝运营 API。代理重写为后端本机 Origin，继续由后端验证会话和管理员角色；浏览器侧无法通过管理门户转发任意地址。

两个门户使用同一 HttpOnly 会话 Cookie，因此切换门户时可以识别当前账号角色，但角色不匹配时只显示正确入口。Cookie 不包含密钥，服务配置继续由 Windows DPAPI 加密保存。

根目录的 `pnpm dev`、`pnpm start` 和 `pnpm build` 同时管理两个应用。若运营端口通过 `AGENTSALE_PORT` 修改，管理端口默认使用运营端口加 2；可用 `AGENTSALE_ADMIN_PORT` 显式覆盖。

当前隔离属于同一设备上的应用与服务端职责隔离。公网部署时还需要独立域名、HTTPS、安全 Cookie、反向代理、集中身份服务和租户级授权。
