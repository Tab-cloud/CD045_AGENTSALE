# 首批工程实现范围

日期：2026-09-06。视觉基线：用户已确认的 v0.2 苹果风方向。此文记录首批可运行切片与原方案的差异，不宣称完整 MVP 已完成。

## 本批实现

Next.js 运营应用，页面包含概览、商品列表/档案、供应商归档、内容、任务、店铺预览与设置。商品、来源、成本、模板草稿、审阅、任务及操作记录写入本地数据库，支持刷新后读取。

主流程：手动录入商品与来源 → 修改人民币采购及美元销售成本 → 保存成本或资料 → 创建评估/模板任务 → 查看持久任务结果 → 编辑脚本 → 审阅/撤回。

来源链接只被保存，没有联网抓取；工厂信息未经独立核实。模板由本地确定性代码生成，不代表调用模型或生成视频。店铺是商品排版预览，无支付/订单接口。

## 本地数据库选择

使用 PGlite 的文件持久化模式及 Drizzle。Windows 默认目录为 `%LOCALAPPDATA%/AgentSale/<项目名及路径摘要>/pglite/`，其他系统默认为项目 `.local/pglite/`。本机 E 盘为 exFAT，实测不能完成 PGlite 初始化；C 盘 NTFS 的写入及关闭后重开已验证，因此运行数据采用独立的用户本地目录。可通过环境变量 `AGENTSALE_DATA_DIR` 指定其他兼容目录。它提供本地嵌入式 PostgreSQL 能力，不使用电脑上已有的共享数据库。官方文档说明其支持文件存储，并使用单个独占连接。[PGlite](https://pglite.dev/docs/)

因此本批只运行一个应用进程。不要同时启动 dev 与 start 指向同一目录，不要由第二个独立 Worker 打开同一目录。共享数据库、独立 Worker 与 Redis/BullMQ 仍需后续工程验证。

本地任务每 1.5 秒消费一个 queued 记录，处理结果与业务对象同事务保存。暂停、继续和重启恢复覆盖本地确定性任务，不保证外部发送的恢复；外部动作尚未实现。进程重启后首次读取工作区会恢复消费者。

迁移 001 位于 `packages/database/src/migration.ts`；schema 对应 `schema.ts`。本批是幂等初始化，不是完整的生产迁移/回滚管理器。数据目录只供本机演练，生产数据迁移、备份与 PITR 另行实施。

## 数据与访问边界

- 服务启动脚本只监听 `127.0.0.1:3045`，显式启用本地模式；API 检查运行模式、Host 和写请求 Origin，拒绝跨站写入。
- 尚未接入 OIDC，不得把本地模式部署到公网或宣称多人权限已完成。
- 每个数据库事务切换到非所有者角色并设置工作区上下文。业务表开启 RLS，读写带工作区限制，关联商品使用跨工作区约束保护。
- 所有写操作带幂等键与服务端参数校验；有版本的修改要求 expectedVersion。
- 来源或成本改变会递增商品版本；旧任务返回资料变化，旧草稿不能直接审阅。人工核对并保存修订脚本后重新审阅。
- 演练确认只记录经营者判断，不等于独立工厂验证或允许发布。无真实外发能力，真实模型、预算执行、支付及发布均未开放。

## 工程安装调整

当前 E 盘为 exFAT，不能按默认方式创建依赖软链接。pnpm 11 采用 `pnpm-workspace.yaml` 中的 `nodeLinker: hoisted`、`packageImportMethod: copy`；源码包通过 TypeScript/Vitest 路径映射读取。配置不放在旧式 `.npmrc`。[pnpm 11 配置变化](https://github.com/pnpm/pnpm.io/blob/main/blog/releases/11.0.md)

保留 workspace 目录组织，暂不通过 workspace 依赖软链接引用内部源码。包依赖版本由 lockfile 固定；安装错误的中间文件不属于可交付业务资产。

`scripts/windows-readlink.mjs` 处理 Windows exFAT 对普通文件调用 readlink 时返回 EISDIR 的差异：只有 lstat 确认不是软链接后，才按工具期望转换为 EINVAL；其他错误保持原样。根目录构建、开发和启动命令统一加载该适配，不能直接用应用子目录的 Next 命令替代。[Next.js 对应问题](https://github.com/vercel/next.js/discussions/38785)
