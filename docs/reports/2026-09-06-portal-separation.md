# 管理与运营门户隔离验收报告

版本：v0.4 / 2026-09-06。

本次交付把管理员页面与运营页面拆成两个独立的 Next.js 前端应用。运营工作台默认使用 `http://127.0.0.1:3045`，管理控制台默认使用 `http://127.0.0.1:3047`。两个入口拥有各自的页面、布局、导航与角色门禁。

## 验收结论

| 检查项 | 期望 | 结果 |
|---|---:|---:|
| 运营账号读取业务接口 | 200 | 200 |
| 运营账号读取管理接口 | 403 | 403 |
| 管理员经管理门户读取管理接口 | 200 | 200 |
| 管理员直接读取业务接口 | 403 | 403 |
| 管理门户代理业务接口 | 404 | 404 |

HTTP 证据保存在 [http-role-check.json](artifacts/portal-separation-v0.4/http-role-check.json)。验收使用隔离数据目录及端口 3046/3048，不修改正常工作区账号与数据。

## 浏览器验收

- 管理员登录管理控制台后，只显示服务配置、账号、额度与调用记录，不显示商品、内容或自动化导航。
- 管理员打开运营工作台时，页面只提供管理控制台入口，不渲染业务界面。
- 运营账号登录运营工作台后，可以看到业务导航，不显示管理配置。
- 运营账号打开管理控制台时，页面只提供运营工作台入口，不渲染管理配置。

浏览器门禁用于界面职责分离，HTTP 验收用于证明服务端不会因隐藏菜单而放松权限。

## 边界

当前实现完成了同一设备上的前端入口、页面树、服务端 API 与角色职责隔离。管理前端只代理身份和管理接口，不代理业务接口。两个门户继续共享本机业务后端和 HttpOnly 登录会话，使错误入口能够识别角色并给出正确跳转。

公网部署仍需配置独立域名、HTTPS、安全 Cookie、反向代理、集中身份服务和租户级授权。本次交付不把本机应用隔离描述为操作系统级或多租户安全隔离。
