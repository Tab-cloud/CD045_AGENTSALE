# Web 服务部署前审核（2026-09-28）

## 结论

代码已具备在**隔离的预发布环境**部署和联调的基础；**暂不批准面向真实付费用户开放**。本次审核没有执行服务器上传。正式开放前必须完成下方的运营、支付与恢复验收，且使用与生产相同的 HTTPS 域名、反向代理和 Node.js 24 环境复测。

Web 的产品职责是账号、订阅、管理员配置和 Agent 服务 API；任务交互与作品展示仍以桌面 Agent 为主。现有 `console` 中的旧业务界面和共享工作区仅供管理员迁移验证，不作为多用户业务入口。

## 接口边界

| 入口 | 主要接口 | 访问要求 |
| --- | --- | --- |
| 会员域名 → 3045 | `/api/v1/auth`、`membership` | 登录、注册；会话 Cookie 或桌面 Bearer Token |
| 会员域名 → 3045 | `gateway`、`knowledge`、`creative` | 有效账号、相应会员权益、服务端额度与资料归属检查 |
| 管理域名 → 3047 | `/api/v1/{admin,creative-config,membership-admin,auth}` | 静态管理页面与受限接口代理；后端再次校验管理员身份 |
| 会员域名 → 3045 | `/api/v1/payments/{wechat,alipay}` | 公开回调；支付签名、商户、金额与订单状态验证 |
| 会员域名 → 3045 | `/api/v1/oauth/{connector}/callback`、`webhooks/{connector}` | OAuth state 或渠道签名/Token；旧渠道数据仍属于管理员共享工作区 |
| 会员域名 → 3045 | 旧 `agent`、`automation`、`commands`、`media` 等 | 公网部署返回 404；仅本机迁移演练可用 |

3045 和 3047 只监听 `127.0.0.1`。反向代理必须分别将两个 HTTPS 域名转发到对应端口，保留请求的 `Host`、`Origin` 与支付签名相关请求头；不要直接开放这两个端口。管理域名建议先以 VPN 或来源 IP 白名单限制访问。

架构更新：3047 已改为静态资源服务与管理接口代理，不再启动第二套 Next 服务。3045 中旧业务接口与自动化逻辑仍是迁移兼容代码，公网部署拒绝调用；这次调整没有声称桌面业务迁移已全部完成。上述构建与烟雾测试数字记录于调整前，正式部署需用新版本重新验收。

本次重构后复核：Node.js 24 下，前端类型检查、132 项测试、会员站点 Next 构建和管理页 Vite 静态构建均通过。隔离端口与临时数据目录中，会员首页和管理首页返回 200、管理账号状态接口返回 200、跨站写入返回 403、管理域名访问旧业务代理返回 404；生产旧业务接口关闭另有单元测试覆盖。临时实例与数据已清理；真实 HTTPS 和支付联调仍未完成。

## 本次已修复和验证

- 公网启动要求不同的 HTTPS 会员/管理域名和源码目录外的绝对数据路径；拒绝开发模式和旧共享工作器。公网不再写入演示商品。
- 旧 Temu 授权回调改用配置的会员域名，回跳到配置的管理域名；固定回调路径和源站验证。
- 渠道 Webhook 在读取过程中限制为 1 MB，避免大请求先完整进入内存。支付回调原本已有 64 KB 流式上限。
- 启用支付时，回调根地址必须与会员站点的公网域名相同。
- `mammoth` 的旧 `argparse`/Lodash 3 链仅供该包的命令行使用，应用只调用 DOCX 解析 API；通过 pnpm 解析钩子和包补丁去除命令行依赖与入口。支付宝 SDK 间接依赖 `urllib` 更新到 4.9.1，二维码链的 `ansi-regex` 更新到 5.0.1。生产依赖审计：`pnpm audit --registry=https://registry.npmjs.org --prod --audit-level high` 无已知漏洞。
- Node.js 24 下运行 `pnpm check`：类型检查、129 项测试和两个 Web 生产构建均通过；`pnpm install --frozen-lockfile --offline` 成功。
- 用独立临时数据目录和模拟 HTTPS 域名运行 `pnpm start`：会员账号状态接口 200、匿名会员接口 401、管理首页 200、匿名管理接口 401。临时数据已清理；这不等于真实 TLS/商户联调。

## 预发布部署条件

1. 用干净且已审核的源码版本部署，不要上传 `.local/`、`node_modules/`、测试资料、开发数据库、`.env` 或桌面打包缓存。服务器安装固定的 Node.js 24、pnpm 11，执行 `pnpm install --frozen-lockfile`、`pnpm build`。
2. 为 3045、3047 分别配置 HTTPS 域名与证书。启动环境至少提供：

   ```sh
   LINGFENG_PUBLIC_URL=https://members.example.com
   LINGFENG_ADMIN_URL=https://admin.example.com
   AGENTSALE_DATA_DIR=/var/lib/lingfeng/pglite
   LINGFENG_SETUP_TOKEN=replace-with-a-random-32-byte-token
   NEXT_TELEMETRY_DISABLED=1
   ```

   口令只放在服务器密钥管理或权限严格的环境文件中，不提交仓库。首次管理员建成后撤掉该环境变量并重启。`AGENTSALE_LOCAL_DEMO` 不要设置为 `1`，`LINGFENG_LEGACY_ADMIN_WORKER` 不要设置为 `1`。使用 `pnpm start` 启动；公网设置不允许 `pnpm dev`。
3. 只运行一份 Web 后端实例。`/var/lib/lingfeng/pglite` 保存数据库，其同级 `/var/lib/lingfeng/automation` 保存加密密钥、服务配置、订单配置与作品。使用独立服务账号、持久卷和限制性文件权限；停写后连同两处目录一起备份并进行恢复演练。当前 PGlite/文件存储不支持多实例横向扩容。
4. 反向代理限制请求体大小与请求频率，特别是注册、登录、初始化、支付下单、模型与媒体接口；记录结构化访问日志但不记录密码、Bearer Token、支付私钥或回调原文。提供磁盘容量、进程与错误率监控。当前应用没有网络级注册/登录限流、账号找回与管理端多因素认证。
5. 初始化管理员后先保持两种支付渠道关闭，仅发布测试套餐并验证匿名、普通用户、管理员的权限边界、桌面登录、权益和额度。然后在商户测试环境验证真实 HTTPS 回调、主动查单、重复通知、订单金额和服务商失败恢复；正式收费前还需退款与订阅撤销流程、对账、客服处理及支付渠道合同验收。

## 当前阻断项

- **真实收费上线阻断：**微信/支付宝尚无真实商户收款、异步通知和退款联动验收，也没有自动对账。保持支付渠道关闭。
- **公网开放阻断：**反向代理的限流、管理域名访问限制、日志脱敏、备份与恢复演练尚未在目标服务器验证。
- **运营完整性：**账号找回、注册滥用防护、管理员多因素认证尚未实现；开放注册前需明确支持与风控流程。
- **发布可重复性：**当前工作区仍有多轮未提交的改动；部署应从审核通过的固定提交与冻结锁文件构建，不能直接复制当前工作目录。

上述事项是上线验收条件，不能由本地单元测试代替。预发布环境可先部署，但不要开启正式付款或对外宣称生产可用。
