# AgentSale 长上下文与记忆架构

## 目标

AgentSale 的对话不是一次性客服问答。经营目标、供应商约束、目标市场、已作决定、订单状态和子 Agent 执行结果会跨越大量消息和多个运行周期。上下文系统必须让模型看到足够的信息，同时满足四个条件：

1. 原始对话不可因压缩而丢失。
2. 模型输入大小有确定上限，不随会话长度无限增长。
3. 长期记忆必须有来源、版本和失效记录，不能把模型猜测写成事实。
4. 每次模型调用都能追溯实际使用的摘要版本、消息和记忆。

## 已实现的产品形态

上下文由四层组成：

| 层级 | 数据 | 用途 |
| --- | --- | --- |
| 事实状态 | Agent 状态、能力、商品、决策、任务、订单、运营记录 | 回答“系统当前真实发生了什么” |
| 近期对话 | 按数据库单调序号保存的原始消息 | 保留最近表达、追问和语气 |
| 滚动摘要 | 目标、长期要求、事实、决定、待确认问题和下一步 | 保留已离开近期窗口的重要内容 |
| 长期记忆 | 偏好、约束、事实和决定的版本化记录 | 跨摘要周期检索经营规则 |

原始消息保存在 `commerce_agent_messages`。消息使用数据库生成的单调序号排序，避免同一毫秒内写入的消息因随机 UUID 排序而错位。

滚动摘要保存在 `agent_context_summaries`。摘要记录处理到的消息序号和版本。达到 24 条未压缩消息或估算 6,000 Token 后，系统压缩较旧消息，并始终保留最近 8 条原文。

长期记忆保存在 `agent_memories`。同一类型和主题出现新内容时，旧版本写入 `valid_to`，新版本保留原始消息 ID 列表作为来源。模型不得把未经渠道或业务状态确认的销量、报价、订单和执行结果写成记忆。

每次自然语言模型调用先建立一个上下文包，并在 `agent_context_runs` 记录：

- 当前消息 ID；
- 摘要版本；
- 选中的近期消息 ID；
- 选中的长期记忆 ID；
- 估算 Token 数；
- 调用状态、用量和上下文维护错误。

## 上下文组装

当前总预算为 12,000 估算 Token，按以下顺序分配：

1. 结构化事实状态最多 2,000 Token。
2. 滚动摘要最多 2,600 Token。
3. 相关长期记忆最多 1,800 Token。
4. 剩余空间从最新消息向前装入，最多 14 条。

中文字符和其他文本分别估算 Token；这不是计费器，而是防止提示词无界增长的稳定上限。后续接入多种模型时，可以按模型配置替换为精确 tokenizer，但上下文管理接口保持不变。

长期记忆首版使用本地词项相关度、记忆类型优先级、置信度和时间排序。经营约束优先于偏好、决定和普通事实。现阶段数据量有限，这比提前引入独立向量数据库更容易审计，也避免新增模型和运维依赖。

## 并发与失败处理

摘要写入在工作区级数据库事务锁内完成，并检查摘要版本。两个并发请求可以读取同一版本，但只有第一个成功提交；另一个不会覆盖新摘要。

上下文压缩属于维护操作。压缩模型失败时，本次对话继续使用旧摘要、长期记忆和近期原文，并把错误写入上下文运行记录。业务对话模型失败时，本次运行标记为失败。原始消息始终保留，可重建摘要。

## 子 Agent 边界

决策、调研、内容、渠道、采购、物流和客服子 Agent 不应共享一段无限增长的聊天文本。调度层为每个任务构造相同格式的上下文包，并额外限定任务所需状态和证据：

- 调研 Agent：经营约束、候选市场、来源和未确认问题；
- 决策 Agent：结构化市场信号、成本、供应能力和历史决定；
- 内容 Agent：已确认商品事实、目标市场、品牌要求和素材权利；
- 履约 Agent：订单、供应商、物流和幂等执行记录。

当前对话入口已经使用上下文管理层。后续各执行 Agent 接入时复用该接口，不复制聊天历史拼接逻辑。

## 开源方案评估

- [LangGraph persistence and memory](https://docs.langchain.com/oss/javascript/langgraph/persistence) 提供线程 checkpoint、持久化和图执行恢复，适合未来复杂状态图；当前运行器已有数据库任务状态和租约，引入后会形成两套执行真相，因此暂不采用。
- [Mem0 open source](https://github.com/mem0ai/mem0) 提供记忆抽取和检索，适合快速构建通用个人记忆；当前业务记忆必须绑定消息来源、工作区和失效版本，原生表更直接。
- [Letta](https://docs.letta.com/) 提供有状态 Agent 和记忆块，适合以 Agent 运行时为产品核心的系统；AgentSale 已有独立决策与执行层，不迁移运行时。
- [Graphiti](https://github.com/getzep/graphiti) 提供时序知识图谱，适合供应商、商品、联系人和事件关系达到较大规模后的关系检索；首版无需承担图数据库运维。
- [pgvector](https://github.com/pgvector/pgvector) 可在 PostgreSQL 内加入向量相似度检索。商品、供应商和记忆规模扩大后，可作为当前 `agent_memories` 的检索索引，保留现有事实表和审计模型。

开源组件将作为可替换能力接入，而不是成为业务事实的唯一保存位置。数据库中的原始消息、结构化状态、来源和执行记录继续是系统真相。

## 验收标准

- 第二轮自然语言模型调用能看到第一轮原始消息。
- 13 轮连续对话后自动形成版本化摘要和长期记忆。
- 每个模型上下文包不超过 12,000 估算 Token。
- 上下文运行均记录完成或失败状态及用量。
- 摘要失败不阻断对话，原始消息可用于恢复。
- 工作区 RLS 同时覆盖摘要、记忆和上下文运行记录。
