# 前端视觉与交互规范

版本：v0.2 / 2026-09-06。按用户“减少 AI 味、参考苹果风”的反馈修订。参考样稿：[可点击界面](../design/agent-sale-preview.html)。样稿为视觉与交互设计，不是生产应用。

## 1. 视觉方向

关键词：简洁、自然、精确、有留白。中文运营后台参考 macOS 工具应用的轻侧栏与内容布局，使用纯白、冷浅灰、石墨黑；蓝色只用于主动作、链接和焦点。重点通过字体大小、位置、间距和细分隔线形成层级。

去掉上一版的绿色大横幅、概念标语、英文全大写眉题、导航编号、彩色胶囊标签和重复提示。页面直接叫“概览”“商品评估”“内容”“店铺”；正文说具体进展。经营后台不放营销口号。

消费者店铺参考 [Apple Mac 页面](https://www.apple.com/mac/) 的商品名称、产品视觉和明确动作的组织方式。应用到本产品时采用原创版式与商品示意，不使用 Apple 标识或其商品素材。后台保持高效浏览，店铺可以给予商品图更大展示空间。

借鉴 Apple 的留白和信息层次，不复制系统窗口红黄绿按钮，不强加浮动玻璃卡片，不用半透明叠层装饰普通表格。模糊仅可用于真实弹层遮罩。

首版默认浅色，提供手动深色和跟随系统。样稿中手动主题仅演示后台主题；正式店铺品牌主题独立控制。

## 2. 设计 token

| Token | 浅色值 | 深色值 | 用途 |
|---|---|---|---|
| canvas | `#FFFFFF` | `#1C1C1E` | 内容画布 |
| sidebar | `#F5F5F7` | `#232325` | 轻侧栏 |
| surface | `#FFFFFF` | `#2C2C2E` | 弹层与输入表面 |
| surface-subtle | `#F5F5F7` | `#272729` | 媒体底板与汇总区域 |
| text-primary | `#1D1D1F` | `#F5F5F7` | 标题与正文 |
| text-secondary | `#6E6E73` | `#A1A1A6` | 注释与次级文字 |
| border | `#E5E5E7` | `#3A3A3C` | 细分隔线 |
| primary-link | `#0066CC` | `#64AAFF` | 链接与焦点 |
| primary-button | `#0071E3` | `#0071E3` | 主动作，按钮文字为白色 |
| selected | `#E8E8ED` | `#38383B` | 中性导航选中背景 |
| warning | `#946100` | `#E4B454` | 必要的待处理状态点及文字 |
| danger | `#B42318` | `#FF8177` | 亏损、失败或危险动作 |

正式组件需测量对比度，正文目标 WCAG AA 4.5:1、非文本控件 3:1；不能仅靠颜色表示状态。token 集中在 `packages/ui`，页面禁止复制自己的颜色表。

字体：优先 `-apple-system / BlinkMacSystemFont / SF Pro Text / Helvetica Neue / Segoe UI / PingFang SC / Microsoft YaHei / sans-serif`。使用设备已安装字体，不分发 Apple 字体文件，不依赖远程字体。页面标题 34/42、600–650 字重，区块标题 20/28、600，正文 14/22，列表 13/21，辅助文字 12/19，非关键版权/演示注释可用 11/17。概览数值 42/52、550，店铺商品名 48/50、600；金额使用 tabular-nums。中文只轻微收紧标题字距。

间距：4、8、12、16、24、32、40、48、60；按钮主交互高度 44px，列表保留足够纵向空间。后台按钮圆角 9px，导航 7px，媒体底板/弹层 14–18px；消费者购买按钮可用胶囊形。概览指标不逐项包卡片，普通列表和待办也不加外框。分组依靠留白和单条分隔线，阴影只用于真实浮层或媒体纸面。

## 3. 运营后台布局

- 桌面 > 1200px：左导航 208px、顶部工具栏 62px、主区水平 padding 48px、顶部 46px，内容最大宽度 1440px。
- 961–1200px：导航 188px、内容水平 30px；概览右列转为下方两项待办。
- 641–960px：导航 172px、内容水平 24px；商品、内容和店铺详情转单列。
- ≤ 640px：顶部四项样稿导航、内容水平 22px；指标保留一行，次要解释简化；表格在自身区域横向滚动，整页不溢出。正式应用的八项导航改菜单，不把八项强塞入移动顶部。

顶部展示工作区、演练/真实状态、全局搜索、需要处理的事项、用户菜单。模式切换走能力检查，不是一个无条件开关。搜索支持商品、供应商、订单和客户，不做凭空编造的全知聊天搜索。

主导航：工作台、商品机会、供应商、内容工作室、推广、客户、订单、经营分析；底部任务与设置。每页只有一个显著主动作，次要动作用描边/文字按钮。

## 4. 页面详细规格

### 工作台

首屏顺序：直接页面标题与一句说明 → 一行三个数值 → 商品列表与待处理事项 → 最近进展。去掉上一版开场大横幅和流程装饰。核心操作靠近标题，当前页面名不再写成情绪化标语。

数值最多 3–4 项，按经营阶段显示候选商品、资料齐备、待处理或实际经营指标。空数据用“— / 尚无数据”，不要渲染虚构增长率。待处理用简洁列表，展示具体对象、状态和下一步。状态默认灰色文字，只有必要的阻塞项显示琥珀色小点，不把所有状态染色。

### 商品机会与详情

列表列：商品/供应地区、目标市场、证据覆盖、预期贡献、阶段、更新时间。排序可按利润或证据覆盖，但缺失成本的商品不能排成已确认高利润。

详情：顶部产品、状态、市场；左侧规格与供应；中间成本拆分和敏感性；右侧缺失证据与建议。成本输入带币种、原始值、换算日期，估算/已核实分开。

主动作按阶段变化：补充资料 → 开始评估 → 进入样品验证 → 准备上架。审阅弹层显示具体商品、市场、金额和影响，不只写“是否确定”。

### 内容工作室

三列：商品事实和素材 → 9:16 视频/分镜预览 → 脚本、主张引用、语言与审阅记录。小屏堆叠。主动作按状态显示生成、重试、通过审阅、导出发布包。

生成中显示已完成步骤、剩余任务与可取消性；失败给出具体原因。没有真实视频时显示“分镜预览”，不绘制假播放成功状态。

### 客户中心

客户列表 + 会话 + 客户摘要。原文/译文切换；AI 草稿与已发送消息视觉区分；引用订单卡只显示该客户可访问数据。明确显示停止跟进、转人工、下一次联系时间。

### 订单中心

订单列表并列显示付款、履约、售后三种状态。详情展示客户可见交期、商品行、采购分配、包裹时间线、成本和异常。退款弹层列明金额、币种、剩余可退额和将调用的服务。

### 任务详情

展示目标、步骤、状态、成本、依据和回执。步骤分类为已完成、进行中、等回复、待处理、已暂停、失败；长等待不显示持续转动的加载动画。提供暂停、继续、补充资料、接手入口。

## 5. 消费者店铺

默认英语样稿不代表首销国家已选择。单商品落地页以银灰背景产品图、商品名称、简短说明、价格和一个蓝色购买动作构成主体。右侧信息保持窄列，减少卖点堆叠；规格、配送和退换使用整齐的文字行。移动端先图后信息。首版正式商品页仍需规格变体、目的地配送预估、退款说明、FAQ 和联系入口。

移动端底部可固定购买区，但不得遮住政策、错误信息或系统安全区。客户不需要知道内部 Agent、供应商报价和任务编排。只有实际有权使用的评价、认证和库存信息才展示，禁止虚构倒计时或“已有数千人购买”。

店铺正式结账由 Shopify 提供，样稿购买按钮只解释该衔接，不收集卡号/地址或创建订单。商品照片必须换成获授权实拍，样稿几何示意不用于销售。

## 6. 通用交互

列表：加载 skeleton、空状态、服务错误、部分数据缺失、无权限、过期状态均设计。保存中防重复点击，冲突展示版本差异；失败保留用户输入。

交互语义：按钮是真按钮，导航是真链接或语义按钮；键盘可达，焦点可见，弹层管理焦点并支持 Escape；必要反馈使用 aria-live。主交互 120–180ms，遵循 prefers-reduced-motion，无持续装饰动画。

金额、时间、状态优先用明确文本。API、token、队列、trace 等实现细节仅在诊断页呈现。界面使用“等待工厂回复”“价格资料已过期”“发布结果待核实”，避免技术错误堆栈直接显示给经营者。

## 7. 本轮样稿范围与后续视觉验收

v0.2 包含概览、商品评估、内容、英文店铺四个视图；保留成本调整、主题、审阅与模拟结账。审阅后概览待处理数量同步更新。一个顶部设计样稿标识与必要的事实状态足够，不在每张卡片重复警告。

文件分为 `agent-sale-preview.html`、同名 `.css` 与 `.js`，均在 docs/design 下；通过本地相对路径加载，无外部字体、图片或脚本服务。复制样稿时需保留三个文件在同一目录。

v0.2 覆盖并替代 v0.1 的暖白/深绿方案。产品功能范围和商业流程未改变。检查记录见 [视觉调整报告](../reports/2026-09-06-visual-refresh.md)。

后续正式前端必须覆盖：1440/1280/768/390px，浅色/深色，键盘、200% 字号/缩放、长中文/英文、空数据、失败、断线恢复。样稿只验证设计方向，不能替代正式应用可访问性或真实业务验收。
