# 外部集成与商业验证

版本：v0.1 / 2026-09-06。所有服务均未在本工作区连接；“计划接入”不代表已经授权或可用。

## 1. 接入优先级

| 集成 | 首版方案 | 接入前置与验证 | 不可用时的可用路径 |
|---|---|---|---|
| 工厂与商品发现 | 用户链接/CSV、获准搜索接口、工厂公开网站 | 来源范围、可访问性、使用权限、引用保存 | 人工导入，不承诺平台全量抓取 |
| 工厂沟通 | 一家已授权企业邮箱提供方 | 收发权限、收件人范围、发送回执、频次控制 | 生成询价文件并人工登记结果 |
| 文本/视觉模型 | 一个主 ProviderAdapter，必要时一个替补 | 凭据、网络、结构化输出、语言质量、费用 | 已有资料可人工处理，任务返回不可用原因 |
| 配音/视频 | 模板剪辑、TTS，可选视频生成 | 商用授权、素材授权、成本、回调、渲染 QA | 素材包和脚本导出 |
| 海外推广 | 一个经过验证的主渠道 | 账号地区、范围、审核、发布流程、回执、指标权限 | 人工发布 + 登记链接 + 指标导入 |
| 电商 | Shopify 单店，GraphQL + webhooks | 店铺、应用权限、商品/订单访问和沙箱 | 本地模拟演示；真实经营可先询盘但不能称交易闭环完成 |
| 支付 | 店铺支持且商户主体可开通的网关 | 主体、地区、品类、币种、退款、结算周期 | 未开通前关闭真实购买，保留询盘 |
| 物流 | 一家供应商/履约服务接口或规范 CSV | 目的国、线路报价、时效、包裹状态和异常字段 | 人工登记且标记来源，不伪造实时跟踪 |
| 客户联系 | 站内咨询和授权邮件先行 | 客户归属、许可、退订、订单身份验证 | 人工接手 |
| WhatsApp/其他社交私信 | 第二阶段逐渠道评估 | 当前官方准入、消息政策、账号权限和成本 | 不列为首版已承诺能力 |

自动化降级仍要完成能完成的步骤；不可用的发布/支付能力必须可见，不能用演练回执冒充真实结果。

## 2. 已核实的关键限制

### 2.1 TikTok

官方 Direct Post 指南限制未审核客户端的公开发布，也明确不接受仅帮助自己或团队所管理账号上传的内部工具。因此本产品的内部运营定位不能直接假定会获批；应评估符合要求的发布服务或保留平台允许的人工流程。每次发布还需满足平台所要求的用户选择与控制。[官方指南](https://developers.tiktok.com/docs/en/content-sharing-guidelines)

这是首版渠道可行性的优先验证项，而非等开发完 API 后再解决的事项。不能靠隐蔽浏览器操作、账号矩阵或绕过审核来补齐缺口。

### 2.2 中国大陆商户收款

Shopify 官方面向中国商户的说明指出，大陆商户可使用第三方支付服务商。我们不能假定 Shopify Payments 或某个独立网关一定适用于实际经营主体。应以店铺后台可开通服务和提供方审核为准，验证付款、退款与结算。[官方说明](https://help.shopify.com/en/manual/intro-to-shopify/initial-setup/sell-in-china/set_up_payments)

### 2.3 回调与幂等

Shopify webhook 不能代替周期性对账，需处理重复、乱序和漏送；GraphQL 幂等支持也取决于具体 mutation/API 版本，不能给所有操作统一假设“平台保证只执行一次”。[Webhooks](https://shopify.dev/docs/apps/build/webhooks) · [幂等支持](https://shopify.dev/docs/api/usage/implementing-idempotency)

## 3. Connector 最小契约

每个连接器实现以下语义：

- `capabilities()`：可用动作、账号范围、权限有效期、沙箱/真实、价格与限制。
- `validate(input)`：检查媒体、金额、语言、目的地、平台强制交互。
- `execute(action, idempotencyKey)`：返回成功回执、异步任务 ID 或结果未知。
- `reconcile(action)`：按外部 ID 或平台幂等键查询，缺少能力时明确返回不可查询。
- `health()`：最近可用时间、凭据过期、限额、请求失败类型。
- `ingestWebhook(rawBody, headers)`：验签、去重与标准事件映射。

统一回执含 `provider/account/action/status/externalId/confirmedAt/cost/error`。capability 状态区分 configured、verified、restricted、expired、unavailable；保存设置只代表 configured。

## 4. 工厂合作的最小资料包

样品结果、SKU/包装资料、供货价与有效期、订单通知方式、接单承诺、发货线路、售后安排、素材授权。报价中须明确人民币金额、税费与国内段运费，国际运费按目标国家与重量尺寸核算。

工厂不支持直接跨境代发时，形成“工厂 → 国内集运/履约商 → 海外客户”的路径，保存国内与国际两段成本和时效。国际物流号和国内快递号分开；消费者交期反映完整链路。

## 5. 市场与品类验证

首销国家尚未确定，本方案不预判某类产品已满足某国准入。为每个 product × market 创建清单，落实适用的标签、认证、知识产权、运输限制、税费/进口责任与售后条件，并记录来源、核实人和日期。

初期选品筛选偏好：规格稳定、易用真实视频展示、尺寸重量可控、质量验证可行、供货条件清晰、退换成本能核算。这些是实验筛选原则，不表示任何品类天然免除监管要求。

优先解决的实物问题：同款一致性、包装后重量、破损/退货成本、送达时效、退货去向、无法交付时赔付责任。没有这些信息，模型的需求分析不足以支撑上架。

## 6. 试点步骤与支出范围

1. 收集 20–30 个候选，核实 3–5 家供应商，挑选 1–3 个商品做样品与小规模验证。
2. 为每个 SKU × 市场记录假设、销售成本情景、最大获客成本和停止条件。
3. 用真实素材制作 2–3 个不同角度的内容；通过一个渠道追踪点击、咨询和成交。
4. 跑完付款、采购、发货、签收与至少一次售后异常演练，再观察真实售后。
5. 结束时给出继续、修改或停止结论，附成本完整度、样本量、缺失数据和证据。

预算待用户设定：研发、云资源/数据库、搜索/模型/视频、店铺与网关费用、样品/质检、物流、推广、售后准备金分别列账。本轮不引用供应商未确认价格，不启动付费服务。

开发环境可以做全部故障演练；真实试点必须具备实际商户与渠道条件。测试购买不能证明结算到银行成功，测试视频也不能证明可以公开发布。

## 7. 真实经营开放清单

负责人与收款主体已确定；目标市场/品类核实完成；供应和售后有约定；店铺政策与商品事实一致；实际支付、退款、结算路径可验证；渠道能够按允许方式发布；预算和授权已配置；客户数据处理已明确；订单异常有接手人。

逐项记录通过证据。尚未通过的具体能力保持关闭，其余已授权的研究和内容准备继续运行。
