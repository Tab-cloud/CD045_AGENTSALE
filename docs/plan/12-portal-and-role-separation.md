# 管理与运营门户边界

版本：v1.0 / 2026-09-06。

AgentSale 在本机启动两个独立的 Next.js 前端应用。运营工作台使用端口 3045，管理控制台使用端口 3047。两者拥有不同的入口、页面树、导航和 API 范围。

| 门户 | 当前访问方式 | 能力 |
|---|---|---|
| Agent 工作台 | 本机直接访问 | 自然语言对话、LLM 回复、任务节点和运行控制 |
| 管理控制台 | 本机直接访问 | 模型与搜索服务、密钥、调用额度、渠道和调用记录 |

根据当前产品阶段，两个入口均已移除登录、退出、账号创建和账号停用。账户管理将在后续统一设计；当前版本只能用于本机单用户开发环境。

后端接口按精确角色划分：

- `/api/v1/admin` 仅接受本机请求，并对写入执行 Origin 校验；
- `/api/v1/agent` 及现有业务接口接受本机 Agent 工作台请求；
- `/api/v1/auth` 已从应用路由移除。

管理前端不打开第二份 PGlite 数据库。它通过固定的本机代理访问 3045 的管理接口，代理只允许 `admin`，拒绝身份和运营 API。代理重写为后端本机 Origin；浏览器侧无法通过管理门户转发任意地址。

两个门户都不读取或转发会话 Cookie。服务配置继续由 Windows DPAPI 加密保存，接口只返回密钥是否存在。

根目录的 `pnpm dev`、`pnpm start` 和 `pnpm build` 同时管理两个应用。若运营端口通过 `AGENTSALE_PORT` 修改，管理端口默认使用运营端口加 2；可用 `AGENTSALE_ADMIN_PORT` 显式覆盖。

当前边界属于同一设备上的界面与接口范围隔离。公网部署前必须恢复身份校验，并补齐 HTTPS、安全 Cookie、集中身份服务和租户级授权。
