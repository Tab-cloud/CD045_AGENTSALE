# 实施任务与交付验收

版本：v0.1 / 2026-09-06。已交付方案、确认版视觉及第一批本地工程。下表保留完整 MVP 的完成门槛；逐项实际实现范围见 [首批工程说明](08-first-implementation.md)，不可把局部实现计作全部完成。

v0.2 进展：新增管理员/运营权限、真实模型与搜索适配器、来源约束的供货选品、持久流程、文案修订、真实 MP4 和媒体包。技术实现与验收见 [自动化方案](09-automation-and-access.md)。这些是 M1/M2 的本地能力，尚不代表真实商业账号或 M3 销售履约已完成。

## 1. 排期假设

建议按 2 名全栈工程师、1 名产品/运营负责人、兼职设计与 QA 估算：约 8–10 个工作周完成可试运营 MVP；真实履约观察另需 2–4 周或按选定线路周期延长。单人开发应按工作量重新估算，不能套用多人日历。

排期为工作假设，不是报价或交付保证。账号审核、商户开通、样品、外部服务授权和运输时间可能构成关键路径。首周就做接入验证，不能等全部功能完工才测试支付和发布。

## 2. 分期交付

| 阶段 | 建议时间 | 交付 | 完成门槛 |
|---|---|---|---|
| M0 定义与接入验证 | 第 1 周 | 当前方案、视觉方向、首销市场/品类选择、渠道/收款验证记录 | 业务负责人决定真实试点参数；各连接器真实可用性有证据 |
| M1 业务基础 | 第 2–3 周 | 登录与工作区、商品/供应商/证据、评估计算、任务账本、演练模式 | 权限隔离、成本计算、模式隔离与基础恢复测试通过 |
| M2 选品与内容 | 第 4–5 周 | 授权搜索/导入、工厂询价、结构化评估、视频模板和审阅 | 一款真实商品资料可形成有依据的内容包；外发仅在授权范围 |
| M3 销售与订单 | 第 6–7 周 | 店铺同步、一个渠道发布路径、邮件/咨询、订单与物流 | 测试支付/退款、采购安排、物流异常与对账通过 |
| M4 加固与试运营准备 | 第 8–10 周 | 故障恢复、安全检查、成本台账、部署恢复演练和操作手册 | 全部 P0 验收通过；真实经营前置项有负责人签认 |
| P1 真实小规模验证 | 开通后按物流周期 | 1–3 个商品、有限预算的完整交易数据 | 可核实订单/交付/成本；明确继续、调整或停止结论 |

工程可在一个主渠道暂不具备 API 发布时交付人工发布包；但该渠道自动发布功能应标为未完成，不能把降级路径计为自动化验收通过。

## 4. P0 验收场景

| ID | 场景 | 必须提供的证据 |
|---|---|---|
| QA-01 | 商品从来源进入评估，缺少国际运费 | 评估显示待补证；无虚构最终利润 |
| QA-02 | 人民币采购、多币种销售、部分退款 | 固定输入的精确计算结果及汇率/税费口径 |
| QA-03 | 模型要求执行未经授权的外发 | 服务端拒绝记录；无外部发送 |
| QA-04 | 同一订单回调重复 10 次 | 一个业务订单/采购意图，无重复外部动作 |
| QA-05 | 付款、退款回调乱序及一次漏送 | 主动对账后与平台当前状态一致 |
| QA-06 | 外部发送成功后 Worker 被终止 | 恢复时查询/人工核实，无盲目重发 |
| QA-07 | 审阅后修改价格/撤销授权 | 原批准不再有效，新动作被阻止 |
| QA-08 | 两个并发任务争用预算 | 实耗与预留不越界，超限动作未发送 |
| QA-09 | 客户要求他人订单/外部页面提示注入 | 不泄露数据，无越权工具调用 |
| QA-10 | 真实 connector 被演练任务调用 | 服务端阻止，演练与真实指标隔离 |
| QA-11 | 部分发货、部分退款、退货额外成本 | 三维订单状态正确，利润不双重扣款 |
| QA-12 | 手机和键盘操作 | 390px 无页面溢出；审阅/错误恢复可用 |
| QA-13 | 数据库备份恢复、Redis 数据丢失 | 恢复报告含实际 RPO/RTO 与未完成动作对账 |
| QA-14 | 真实发布、真实支付与实际交付 | 各自独立记录；未执行项不得标为已通过 |

Agent 专项用例 [AG-01–AG-10](03-agent-workflows.md) 与以上场景交叉映射，避免重复编写只验证实现细节的测试。

## 5. 质量与性能目标

关键金额/权限/幂等/模式隔离必须自动化测试；前端主路径通过浏览器验收；素材通过真实播放与人工审阅。禁止仅凭构建成功宣布业务闭环通过。

初始目标：目标容量下列表/API P95 < 1 秒（不含外部生成服务），webhook 验签并持久入库 P95 < 2 秒，正常队列开始执行延迟 < 30 秒。测量环境、样本量与数据规模写入报告；视频时间按实际供应商测量，不承诺固定生成秒数。

任何一次发布必须同时交付：改动文件范围、运行方法、迁移影响、测试结果、模拟/真实证据区分、已知缺口、回滚/恢复方法。只提交属于任务范围的文件。

## 6. 风险及对应动作

| 风险 | 影响 | 优先动作 |
|---|---|---|
| 主渠道不允许内部直发工具 | 自动宣发路径无法直接落地 | M0 验证；允许的发布服务/人工路径，明确完成范围 |
| 收款主体或品类无法开通 | 无法真实结账 | M0 验证网关，禁止先搭假付款闭环 |
| 供应商信息和库存不稳定 | 错卖、延误、售后损失 | 样品、报价有效期、库存刷新、接单确认 |
| 视频效果与商品不符 | 客诉与损失 | 实拍优先、事实引用、审阅、素材版本 |
| 无法确认外部动作是否成功 | 重复联系或交易 | 幂等记录、回执、主动对账、结果未知状态 |
| 获客成本高于利润空间 | 自动化扩大亏损 | 实验预算、成本追踪、停止规则 |
| 人手与范围超出假设 | 周期延长 | 按优先级完成单市场单渠道闭环 |

## 7. 第一批可直接开工的工作

从 T01–T08 开始，优先完成“导入商品 → 保存证据 → 计算情景利润 → 生成任务 → 人工审阅”的可运行切片。以虚构 fixtures 验证完整流程，在真实账号未准备好时继续开发基础能力。

第二批连接真实资料、内容生成与电商沙箱。任何从演练进入真实经营的步骤，都要在报告里写清账号、授权、实际操作和回执，不能沿用样稿截图作验收证据。
