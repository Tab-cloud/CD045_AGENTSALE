# 执行总纲与产品决策

版本：v0.1 / 2026-09-06。状态：可开始产品与工程基础建设；商业接入条件仍需验证。

## 1. 已确认的定位

中国大陆工厂货源 → 海外市场 → 我们的品牌店铺成交 → 工厂或履约服务商交付。

平台帮助经营者持续找到值得卖的商品、确认供应能力、制作本地化营销内容、跟进海外客户，并根据订单和成本数据调整经营策略。选品单位是“商品 × 目标市场”，不输出脱离市场的通用盈利保证。

参考客隆体 AI 的内容生产、客户记忆与持续跟进思路；其官网不是海外渠道接入及交易履约能力的实测证据。[参考官网](https://consumerclone.com/)

## 2. 产品形态

### 2.1 中文运营 Web 后台

面向我们自己的运营团队，桌面浏览器为主，手机用于查看异常、审阅内容和跟进客户。首版不开发 Windows 安装包或原生移动 App。

- 一个工作区管理商品、供应商、内容、客户、订单和任务。
- 工作台先展示需要做的决定、经营进度和异常，而非聊天输入框或 Agent 头像墙。
- 自然语言用于发起目标，例如“评估这批产品在目标市场的销售机会”；每个目标必须落到可查看的业务对象和操作记录。
- 经营者可查看依据、修改方案、设定授权范围、暂停任务和接手异常。

### 2.2 海外消费者品牌店铺

独立品牌域名、移动端优先、首发一种语言和一种结算币种。默认技术路径为 Shopify 主题店铺及其结账能力，AgentSale 管理商品准备与运营，已发布商品、支付和订单以电商平台记录为准。

首版支持标准商品直接购买，复杂问题通过商品页询盘或站内咨询承接。不自研购物车、支付网关、税务引擎，不在首版建设多供应商公开入驻市场。

### 2.3 后台持续执行服务

运营人员关闭页面后，已授权任务仍可执行、等待回复、恢复和提醒。供货与销售两个方向使用不同的知识和权限，同享商品事实、成本与订单记录。

## 3. 商业模式默认决策

| 项目 | 本版设计选择 | 状态 |
|---|---|---|
| 货源 | 中国大陆工厂产品，可记录贸易商但不得冒充工厂 | 用户已确认货源方向 |
| 市场 | 海外市场，按国家单独核算和准入 | 用户已确认方向；首销国家待定 |
| 买家 | 标准实物商品的海外消费者，保留询盘入口 | 本版默认，待经营者确认 |
| 收益 | 我们按销售差价经营，记录采购成本 | 本版默认 |
| 二级分销 | 工厂 → 我们 → 客户；不实现上下级推广佣金 | 含义待用户最终确认 |
| 履约 | 优先有明确服务条件的代发；必要时对接集运/履约商 | 需供应商验证 |
| 资金 | 我们对客户收款，再按合作约定支付供货款 | 默认；结算周期与主体待定 |
| 库存 | 首版不自建仓库；供应商库存有时效与可售量规则 | 工程默认 |
| 产品销售 | 先内部自营验证，后续才考虑对外 SaaS | 本版默认 |

“我们是卖方”意味着需要落实交付和售后责任，不能把工厂发货理解为无需处理客户问题。收款主体、合同主体、出口/进口责任和税费承担需在真实开售前逐项明确。

## 4. MVP 范围

支持 1 个经营工作区、1 家店铺、1 个目标市场、1 个主渠道、1 种主要销售语言。试点容量建议为 20–30 个候选商品、3–5 家候选供应商、1–3 个实际上架商品；这些是验证规模建议，不是业务承诺。

必须形成三个可独立验收的闭环：

1. **选品闭环**：导入/发现商品 → 证据与成本整理 → 工厂信息核实 → 市场评估 → 测试或放弃。
2. **获客闭环**：可信商品资料 → 视频与商品页草稿 → 审阅 → 发布回执 → 引流归因 → 客户跟进。
3. **订单闭环**：付款确认 → 供应商接单 → 发货/配送 → 异常/售后 → 成本对账。

首版自动发现从“经授权的搜索接口 + 工厂公开网站 + 人工提供链接/表格”开始。对需要登录、验证码或数据许可的平台不承诺全量抓取。

## 5. 两种运行模式

- **试运营/演练**：使用明确标识的合成数据与沙箱连接器；可比较毛利、生成预览、模拟任务，无真实发信/发布/扣费/采购。
- **真实经营**：真实凭据、商户、数据源和授权全部就绪后启用；按工作区、连接器和动作逐项开放。

技术上模式是服务端强制属性。把界面标签从“演练”改成“真实”不会开放权限，合成订单不得计入实际收入。

## 6. 首版成功标准

工程成功：关键流程在重复回调、网络超时、工作进程重启和授权撤销下不产生重复订单、重复发信或错误付款状态；每次行动能追溯到依据与回执。

商业成功：小规模真实试点完成可核实的获客、订单交付与利润复盘。盈利与稳定成交需要观察数据，不以预览视频、测试支付或展示数字替代。

不预设“播放量达到某值就成功”。每个商品测试前设定预算、最低贡献利润、最大试验损失、观察周期和停止条件。无成交也可以得出应停止该商品的有效结论。

## 7. 尚待经营者输入，但不阻塞方案与基础开发

| 问题 | 未决时的工程处理 | 必须定案的节点 |
|---|---|---|
| 首销国家与语言 | 可配置；样稿仅展示英文、美元示例 | 市场评估真实试点前 |
| 第一品类 | 使用虚构无电日用品展示数据结构 | 样品采购/准入评估前 |
| 收款和经营主体 | 电商连接器沙箱 | 真实支付前 |
| 预算、亏损上限、折扣底线 | 对外支出额度为 0 | 真实付费调用、采购或投放前 |
| 工厂资源及是否支持代发 | 人工导入与询价草稿 | 商品开售前 |
| 主推广平台及账号 | 素材导出和发布记录 | 渠道实测前 |
| 分销的具体含义 | 无上下级佣金数据模型 | 佣金模块立项前 |

本方案中的页面、结构和技术选型是可修改的默认决定，不需要等待以上答案才能开始 M0/M1。进入真实交易的对应动作必须有具体业务配置。

## 8. 建设顺序

先确立业务事实与价格计算，再建设持久任务和连接器，然后接通选品、内容、销售及订单。最后用真实小规模数据评估自动化效果。
