# AgentSale 调研工具运行时

## 目的

调研能力属于 Agent 的执行层。LLM 负责判断下一步需要搜索什么、读取哪些候选来源以及何时具备交给证据审查模型的资料；运行时负责验证参数、限制权限、调用外部服务和保存结果。模型不能直接访问网络，也不能把计划当作已经执行的结果。

## 已实现结构

`ToolRegistry` 是统一工具注册入口。每个工具包含稳定名称、用途、Zod 输入 Schema 和执行函数。计划器只能从注册表目录中选择工具，运行时会再次解析输入。

当前工具：

| 工具 | 输入 | 返回 | 实现 |
| --- | --- | --- | --- |
| `web.search` | 3–400 字符的查询 | 标题、摘要、规范化 URL、来源服务 | Brave Web Search |
| `web.fetch` | 搜索发现或用户提供的公开 URL | 标题、清理后的正文、内容哈希、采集时间 | 安全 HTTP Fetch + Cheerio |

研究循环最多运行 3 轮、搜索 3 次、抓取 8 个页面，每轮最多接受 4 个动作。空查询、重复查询、超限调用以及并非由搜索或用户提供的 URL 都会被拒绝。成功、失败和拒绝均写入任务的 `toolRuns`，包括轮次、输入、摘要和时间。

流程如下：

1. 创建研究状态，包含经营目标、搜索是否可用、候选 URL、搜索摘要、已保存来源和先前工具结果。
2. 模型以严格 JSON Schema 返回工具计划，不直接生成研究结论。
3. 工具注册中心验证动作和参数。
4. 搜索结果进入候选 URL 集合；正文去重后进入来源证据。
5. 下一轮模型根据新增证据继续搜索、抓取或结束。
6. 原有供应商研究模型根据保存的全文证据生成结构化判断，并执行逐字引用验证。

## 数据边界

- 搜索密钥和模型密钥仅由服务端密钥库读取，不进入模型上下文或工具轨迹。
- `web.fetch` 延续已有 SSRF 防护：只允许 HTTP(S)，拒绝本机、内网、云元数据和非标准公网端口，DNS 检查后固定连接地址。
- 自动读取遵守 robots.txt；无法确认规则时停止，不绕过登录或访问限制。
- 搜索和抓取结果属于不可信数据。模型提示词明确禁止执行网页内嵌指令。
- 来源保存 URL、正文哈希和采集时间；最终供应商、代发及国家配送结论仍必须逐字引用来源。

## 当前限制与下一扩展点

当前 `web.fetch` 处理公开静态 HTML。JavaScript 渲染页面、PDF、表格、图片 OCR、需要账户授权的数据和平台内部指标不在本次实现中，也不会被标记为已完成。

后续工具通过相同注册协议增加：

- `browser.render`：在 HTTP Fetch 无正文时使用受限 Playwright/Crawlee 工作器；
- `document.extract`：解析 PDF、CSV、XLSX、DOCX 和图片，并保留页码或单元格定位；
- `evidence.search`：从历史来源和上下文记忆中检索已采集证据；
- `platform.query`：调用已授权的 TikTok Shop、Temu 或供应商接口，不使用网页抓取模拟授权数据。

动态浏览器必须作为独立工作器接入现有域名策略、页面数限制、超时和审计后才能开放给计划器。不能把无网络边界的浏览器对象直接交给模型。

## 验收条件

- 没有用户 URL 时，Agent 能规划一次搜索，再选择搜索结果进行抓取。
- 有用户 URL 时，无需搜索密钥即可规划并读取该 URL。
- 未经搜索或用户提供的 URL 被拒绝，抓取函数不会执行。
- 搜索、抓取、失败和拒绝均保存在任务轨迹中并显示在运营页面。
- 已保存来源继续通过原有逐字引用验证后，才能形成可执行的供应商与市场建议。
- 来源不属于供应商或没有候选商品时，证据审查允许返回空候选；系统不会为了满足 Schema 强制制造一个供应商。
